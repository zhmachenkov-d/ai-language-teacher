Rule draft: teaching domain depends only on ports; adapters implement LLM, voice, Telegram, persistence, clock/scheduler; Vue is a driving adapter via IPC.
- (decision) Process topology: Electron main = thin host (window, process lifecycle, IPC bridge only — no teaching business logic). Prevents: pedagogy/scheduling leaking into Electron.
- (decision) Schedule + reminder/micro-lesson delivery ownership: Python teacher runtime, continues when UI closed. Prevents: reminders dying with Electron window; UI owning cadence.
- (decision) Telegram = driving/driven adapter to same teaching domain (not a separate bot domain model). Micro-lesson results sync into same Progress/error path. Prevents: dual learner state between bot and desktop.
- (decision) STT/TTS: in-Python (local stack), not third-party cloud voice services. Prevents: voice vendor lock-in and PII audio leaving machine via cloud STT/TTS. OPEN: tension with NFR-2 voice quality bar — need quality bar / fallback stance.

- (decision) Runtime: Python teacher is a background service (tray/user-service); Electron is UI client only (connects via IPC/local API). Closing window does not stop scheduling/Telegram delivery. Prevents: reminders tied to UI lifetime; Electron owning teacher lifecycle beyond start/stop UX.
- (decision) Voice port: local-first STT/TTS inside Python service, with explicit optional cloud fallback behind the same port. Prevents: UI calling cloud voice directly; dual voice stacks; silent cloud use without config. NFR-2 satisfied via local quality bar + opt-in fallback.

- (decision) Living plan mutations: teacher-only via LLM-orchestrated use cases; UI/Telegram are read + command-to-teacher, not direct plan writers. Prevents: divergent plan editors; UI rewriting curriculum outside pedagogy rules.
- (decision) Progress/errors: single write-path shared by lesson and micro-lesson completion (same domain service). Prevents: dual stat stores that diverge between desktop lesson and Telegram micro-lesson.
- (decision) In-progress lesson session persists for resume (not ephemeral-only). Prevents: lost mid-lesson state on crash/close; UI inventing its own resume cache as source of truth.
- (decision) Persistence: SQLite as single local source of truth for plan, session resume, progress/errors, learner prefs, Telegram link metadata. Prevents: split JSON/file stores diverging; UI-local caches as authority.

LangGraph owns in-phase LLM agent loops (prompts, tool/port calls, explain/correct/ask branching). Graph must not write SQLite directly — only via domain use cases. Prevents: dual lesson controllers; graph bypassing pedagogy invariants.

Electron is client + lifecycle only; Telegram adapter and UI both use domain via service, not Electron IPC as domain bus. Prevents: dual domain contracts; domain calls trapped inside Electron when UI closed.

Secrets (LLM/Telegram/optional cloud voice) via config port on disk with OS permissions; never injected into LLM prompts as identity (NFR-1). Prevents: LAN exposure; unauthenticated local process calling teacher; keys leaking into prompts.
